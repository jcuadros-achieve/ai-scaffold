ai-scaffold

Installs a standardized AI workflow structure (CLAUDE.md, .claude/, .context/) into any project. One command to get the entire team working with AI consistently.

⬢ main — v2.8.x (classic) ✦ feature/redesign — v2.9.0-rc.1 (inverted)
Context

What problem does it solve?

Without ai-scaffold

  • Every repo has its own CLAUDE.md — inconsistent across projects
  • The agent has no context: stack, decisions, protected zones
  • No persistent memory → AI repeats mistakes across sessions
  • No workflow → devs decide ad-hoc what to ask Claude
  • No gates → code merged without real verification

With ai-scaffold

  • Single source of truth: CLAUDE.md + .claude/ per project
  • AI contextualized to the project: stack, ADRs, own patterns
  • Append-only memory → decisions and sessions persist
  • Disciplined workflow with human gates between every step
  • Real verification (build/tests/lint/audit) before any PR

.context/ structure

.context/
├── adr/ # ADRs — append-only
│ └── ADR-001-*.md
├── ai-log/ # Session logs
│ └── 2026-06-17.md
└── INDEX.md # Auto-regenerated
How it flows automatically
  • On plan approval → /task-implement writes the ADR at step 0, before any code
  • On task close → /ai-log-write logs the full session
  • On PR → /pr-write verifies ADR vs code, refreshes INDEX
  • Rule context instructs the agent: "read .context/ before proposing anything"

Product evolution

main vs feature/redesign

Dimension main · v2.8.x redesign · v2.9.0-rc.1
Install model CLI installs a predefined set of skills/rules directly Inverted flow: install lays only a minimal seed; ai-init curates the rest
What does install write? Core rules + full skill set by default Seed only: skill/ai-init + rule/context. Everything else is offered, not imposed
Who decides what to install Hard-coded in the CLI Agent scans the real repo, curates with the human, generates an explicit plan
Catalog No formal catalog, flat files 76 entries in catalog.index.json with appliesWhen, version, hash per entry
Agents Not included 9 specialized agents (reviewer + builder per stack)
Updates / drift Manual, no tracking 3-way merge: clean / customized / conflict. Conflicts never auto-applied
Monorepo support No ADR-013: ai-init detects workspaces and generates per-workspace CLAUDE.md
feature/redesign — Keystone

/ai-init — The inverted flow

ADR-017: the agent, not the CLI, decides what to install. It analyzes the real code → curates with the human → CLI executes. The decision always belongs to the human — the agent proposes, never imposes.
